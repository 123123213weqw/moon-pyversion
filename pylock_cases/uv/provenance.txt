Real `pylock.toml` documents, written by uv (a third-party implementation).

These files are the only documents in the differential corpus that this repository
did not write. Everything under `pylock_cases/*.toml` is generated by
`tools/fetch_pylock_corpus.py` from the specification; everything here was produced
by another tool, so it is an input from outside this project.

What that is worth, and what it is not worth
--------------------------------------------

The *inputs* are independent. The *verdict and projection* for the records built
from these files are still this repository's reading of PEP 751 -- uv cannot be
asked for a verdict, so no external oracle exists for that half (see
`docs/experiment-results.md` §6.9). What these files do show is that a tool with
its own, independently written understanding of PEP 751 emits documents this reader
accepts: real index URLs, real sha256 digests and sizes, `wheels = [...]` inline
arrays, and `index` members. The self-authored curated documents could not show
that, because one person wrote both sides of them.

They are committed rather than regenerated, for the same reason the real `METADATA`
documents are: a newer uv would silently change what the corpus covers. Re-running
`regenerate.sh` is a deliberate act and requires updating this file.
